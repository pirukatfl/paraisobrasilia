# Resumo: mensagens de erro claras (site e painel)

- Novo módulo puro `src/lib/errors/` (`index`, `mensagens`, `traduzir`, `after-error`, `endpoint`, `server`): `mensagemAmigavel(err)` (ServiceError/APIError público/ValidationError mantêm o texto; códigos Postgres 23505/23503/23502/22001, conexão e limite de arquivo viram frases em português; resto = `MENSAGEM_INESPERADA`; nunca expõe SQL, tabela, stack ou caminho), `traduzirMensagem` (dicionário das frases em inglês do Payload), `mensagemDaResposta(status, json)` (`message` -> `errors[0].message`/`data.errors[]` -> texto por status 401/403/404/413/429/5xx), `mensagemDeFalhaDeRede`, `mensagemDeExcecao`.
- `payload.config.ts`: `hooks.afterError` (`traduzirErroDaApi`) reescreve toda resposta de erro da API com `message` no topo e `errors[].message` em português, refazendo a partir do erro original quando o Payload trocou por "Something went wrong."; `errors[].data/field/path` e o status ficam intactos (o formulário do painel continua destacando o campo). Painel só em português (`supportedLanguages: { pt }`, removido `en`).
- Endpoints customizados (classisex, assinantes, mensagens): erro inesperado agora vira `{ message }` em português com status 500 e vai para o log (`respostaDeErroInesperado`), em vez de ser relançado.
- Painéis do admin (`Moderacao`, `Denuncia`, `MensagemDenuncia`, `Assinatura`, `aprovar-lista`, `AprovarSelecionados`, `AprovarCelula`, `EmailConfirmado`, `AvisoSemData`): `json.message ?? 'Erro'` e `'Não foi possível concluir.'` trocados por `mensagemDaResposta(res.status, json)`; falha de rede/`Failed to fetch` por `mensagemDeExcecao`.
- Site: `VisitorAdForm` (corpo não-JSON como 413/502 usa o status; rede usa texto próprio), `AdForm` (upload XHR: 413 = arquivo grande, falha de rede = código `rede`), `InfiniteAds` (texto com motivo e como tentar de novo). `media-messages.ts` ganha códigos `rede` e `erro` e o texto padrão de upload deixa de ser genérico.
- Server actions: `classisex/actions.ts` (salvar, apagar, mídia, denunciar), `mensagens/actions.ts` (iniciar, responder, bloquear, desbloquear, denunciar) e `assinantes/actions.ts` (entrar, trocar senha, cadastrar) tratam erro inesperado com texto em português (estado do formulário ou `?erro=inesperado` exibido nas páginas `entrar`, `senha`, `meus-anuncios`, conversa e `SignupForm`), logam o original e usam `unstable_rethrow` antes, para nunca engolir `redirect()`/`notFound()`. `more-actions.ts` continua relançando (o `InfiniteAds` já mostra o motivo). Route handler de upload do assinante (`meus-anuncios/[id]/midia`) ganhou rede de segurança que volta para a página de edição com mensagem.
- `(frontend)/error.tsx`: texto genérico correto para qualquer página, "Código: digest", "Tentar de novo" e "Voltar ao início"; novo `src/app/global-error.tsx` (falha no layout raiz, HTML mínimo com estilo inline). Nunca mostra `error.message`.
- Docs: seção "Quando aparece um erro" em `docs/painel/GUIA-DA-EQUIPE.md`.

Decisões/diferenças: rotas de imagem (`midia/[id]/[variante]`, `classisex/previa/[id]`) não mudaram (servem binário para `<img>`, já devolvem 403/404 e o erro de disco é logado). Ações `void` de recuperação de senha, confirmação de e-mail e `definirNovaSenha` seguem caindo no `error.tsx` novo (com código).

Resultados: `pnpm typecheck` limpo; `pnpm lint` limpo; `pnpm test:unit` 43 arquivos/442 testes ok (novos: `tests/unit/erros.test.ts` e `tests/unit/erros-api.test.ts`).
