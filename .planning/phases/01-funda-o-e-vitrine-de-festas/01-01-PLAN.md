<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet → /admin | Untrusted users can reach the Payload login and REST API |
| npm registry → build | Third-party code enters the build |
| developer machine → git | Secrets could be committed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Spoofing | Payload `users` login | mitigate | `auth.maxLoginAttempts: 5`, `lockTime: 600000` in src/collections/Users.ts |
| T-01-02 | Elevation of privilege | `POST /api/users` (self sign-up) | mitigate | `access.create = ({ req }) => Boolean(req.user)`; first user only through Payload's first-register screen; int test in plan 01-09 asserts anonymous create is rejected |
| T-01-05 | Information disclosure | `.env`, PAYLOAD_SECRET | mitigate | `.gitignore` covers `.env*` except examples; acceptance check `git ls-files` |
| T-01-04 | Information disclosure | Postgres port | mitigate | compose binds `127.0.0.1:5432` only |
| T-01-SC | Tampering | npm installs | mitigate | Task 1 blocking human verification of every [ASSUMED] package; exact version pins; pnpm lockfile committed |
</threat_model>
