# Phase 06.1: Galeria de modelos com página por modelo - Research

**Researched:** 2026-10-23
**Domain:** Payload 3.91 collection evolution (array limits, slug, upload arrays, drafts) + Next 16 dynamic route with tagged cache
**Confidence:** HIGH (everything below was read in this repo; Payload behaviours marked VERIFIED were confirmed in existing migrations/tests)

## Summary

The Phase 2 models gallery (02-04) is a single page `/modelos` with cards that open a lightbox of 1–3 photos. Phase 06.1 turns each card into a link to `/modelos/<slug>`, a public page (age gate only) with the artistic name, a short description and up to 30 photos + up to 3 videos. Almost every building block already exists and should be reused rather than rebuilt:

- **Slug + per-document page:** the Dicas Hot quick task (`src/collections/Dicas.ts`, `src/app/(frontend)/dicas-hot/[slug]/page.tsx`, `src/lib/dicas/public.ts`) is the freshest analog: `beforeValidate` slug default from the title, pt messages, uniqueness check with `withRequestState`, `SLUG_RE`/`SLUG_MAX`/`slugify` from `src/lib/contos/excerpt.ts`, `generateMetadata` + `buildPageMetadata({ image })`, `notFound()` when not published.
- **Photo + video grid with lightbox:** `src/components/Gallery.tsx` already renders photo and video tiles (poster + "Vídeo" badge + play icon), no-JS link fallback, and opens the shared `Lightbox` (video only for the active slide, `preload="metadata"`). It takes `SpaceItemDTO[]` (`{ id, kind, caption, image, video }`), so a model page can feed it directly by mapping photos/videos to that shape — **no change to Gallery.tsx or Lightbox.tsx is needed**.
- **Mapping media:** `toGalleryImage()` in `src/lib/gallery/queries.ts` (gallery 1600 px for the lightbox, card 640 px for tiles, alt fallback) and `toSpaceItemDTO()` for the video branch (`video.url`, `video.title`, `poster`).
- **Cache + fast removal:** `cached()` + tag `'models'`; `revalidateModels` already expires `'models'` on every change/delete of a model, and `revalidateGalleries` (Media hooks) expires `'models'` when a photo's alt changes or a file is deleted. The detail page can reuse the same tag — unpublishing any model expires every model page at once.
- **Contact hygiene:** `redactContacts()` (`src/lib/classisex/redact.ts`, pure module, already reused by `src/lib/recados/rules.ts`) detects phones, e-mails, URLs, `@handles` and "zap/insta" keywords. A model description/name that would be redacted is refused in the panel.

**Primary recommendation:** evolve in place — same `models` collection, same tables. Migration 1 adds `slug` + `description` (columns on `models` and `_models_v`) and backfills the slug of existing models from the name; the 3 → 30 widening is config-only (no DDL). Migration 2 adds the `videos` array (`models_videos` + `_models_v_version_videos`). No column is dropped or renamed, so existing models keep working without staff rework.

## Architecture Patterns

### Data model (after the phase)

| Field | Type | Notes |
|-------|------|-------|
| `name` | text, required | unchanged; contact check added |
| `slug` | text, required, unique, index, sidebar | NEW. Default `slugify(name)`, auto-suffixed `-2`, `-3` when taken; staff-typed slug validated (`SLUG_RE`) and must be unique (pt messages) |
| `description` | textarea, maxLength 300 | NEW, optional. Contact check |
| `photos[]` (`image` → media) | array, minRows 1, **maxRows 30** | same table `models_photos`; custom pt validate |
| `videos[]` (`video` → videos) | array, maxRows 3, optional | NEW table `models_videos`; custom pt validate |
| `order` | number | unchanged |
| `imageAuthorization` | group (staff-only read) | unchanged |

VERIFIED (migration `20261019_032314_models.ts`): in this drafts-enabled collection required fields are created **nullable** (`"name" varchar`), so adding a required `slug` does not need a default for existing rows; the unique index allows multiple NULLs until the backfill runs in the same migration.

### Migration backfill (existing models keep working)

`migrate:create` generates the DDL only. Append a backfill to `up()` that calls an exported, plain-Node helper `backfillModelSlugs(db)` from `src/lib/gallery/model-slug.ts`:
1. `SELECT id, name FROM models WHERE slug IS NULL ORDER BY id` and the set of existing slugs.
2. For each row: `uniqueSlug(slugify(name) || 'modelo', taken)` → `UPDATE models SET slug = … WHERE id = …`.
3. `UPDATE _models_v v SET version_slug = m.slug FROM models m WHERE v.parent_id = m.id AND v.version_slug IS NULL` (so the admin form, which loads the latest version, shows the slug).

The helper is idempotent (only NULL slugs) and is int-tested by nulling a slug with SQL and running it.

The `beforeValidate` hook also fills an empty slug on **update** (`data.slug ?? originalDoc?.slug` empty → generate from `data.name ?? originalDoc?.name`), so even a row missed by the backfill heals on its next save.

### Reads and DTOs

- `getPublishedModels(): ModelCardDTO[]` — `{ id, slug, name, cover: GalleryImage, photoCount, videoCount, updatedAt }`; same query as today (published, `sort ['order','name']`, depth 2, limit 60), tag `'models'`. `hasPublishedModels()` unchanged.
- `getPublishedModel(slug): ModelPageDTO | null` — `{ id, slug, name, description, items: GalleryItemDTO[], cover, ogImage, photoCount, videoCount, updatedAt }`; returns `null` for a slug failing `SLUG_RE` (no query), a draft, or a missing doc. Cache key `['gallery:model']`, tag `'models'`.
- `GalleryItemDTO` = alias of `SpaceItemDTO` so the page passes `items` straight to `<Gallery>`.
- Caps applied in the DTO too (`.slice(0, 30)`, `.slice(0, 3)`) — defence against data written before validation.

### Page

`src/app/(frontend)/modelos/[slug]/page.tsx`: `dynamic = 'force-dynamic'`, `generateMetadata` (title = name, description = description or `'{nome}, modelo do Paraíso Brasília: fotos e vídeos.'`, canonical `/modelos/{slug}`, OG image = cover `og` derivative 1200×630 if present else the cover), `notFound()` when `null`. Server component; the only client island is `Gallery` (+ Lightbox), already budgeted in Phase 2.

### Anti-Patterns to Avoid
- **Changing `photos` to an `upload hasMany` field** to get bulk upload: it moves data from `models_photos` to `models_rels` (data migration, risk) — violates "only widen limits and add fields".
- **A second cache tag per slug** (`model:{slug}`) — unnecessary: every model write already expires `'models'`; one tag keeps the "Despublicar → off at once" guarantee simple.
- **Client-side hiding of drafts** — always `where _status = published`, `draft: false` on the server.
- **Touching `Gallery.tsx`/`Lightbox.tsx` APIs** — they are shared with /espaco and the ClassiSex members gallery (`plainImages`); reuse through DTO shape only.

## Common Pitfalls

1. **Parallel migrations (ClassiSex workstream).** Payload `migrate:create` diffs against the latest `*.json` snapshot in `src/migrations/`. If the other branch merges a migration after ours was generated, the next generated migration would re-emit their DDL. Mitigation: `git fetch` + rebase on the current `main` immediately before `migrate:create`; the deploy plan re-runs the whole chain on a fresh test DB (`vitest` global setup migrates) and refuses to push if `migrate:create` on top of everything would produce a non-empty diff.
2. **Generic Payload validation message.** VERIFIED (02-04 SUMMARY): Payload throws a generic "O campo a seguir está inválido"; the pt message lives in `error.data.errors[].message`. Keep custom `validate` on arrays and assert there.
3. **`maxRows` literal vs constant.** 02-04 wrote `maxRows: 3 // MAX_MODEL_PHOTOS`; acceptance greps must target the new literal `maxRows: 30` and `maxRows: 3` (videos) — keep literals + comment.
4. **Draft versions readable by any logged-in principal.** Models has no `readVersions`; Payload's default is "any authenticated user", which includes subscribers (`assinantes`). Add `readVersions: isStaff` (same as Dicas/Contos).
5. **Videos edits don't expire caches.** `Videos.ts` has no hooks; a renamed/deleted video would stay on a model page for up to 10 min (`CACHE_SECONDS`). Add `revalidateGalleries`/`revalidateGalleriesAfterDelete` (expires `'space'` and `'models'`). This file is shared only with the space gallery (ClassiSex uses `ad-media`).
6. **List payload size.** Depth 2 with 60 models × 33 relations is fine for a cached query (one DB read per 10 min/edit) but the DTO must keep only the cover + counts so the RSC payload of /modelos stays small.
7. **30 photos on a phone.** `Gallery` loads 2 tiles eagerly and the rest `loading="lazy"` from the 640 px `card` derivative with `sizes` 50vw on phones; the mobile budget test proves the first view stays ≤ 600 KB.

| Threat | STRIDE | Mitigation |
|--------|--------|------------|
| Draft model readable through `/api/models/versions` by a subscriber | Information disclosure | `readVersions: isStaff` + int test |
| Contact typed in description reaches the open page/Google | Information disclosure / policy | `redactContacts` validate on name + description |
| Unpublished model still served from cache | Information disclosure | tag `'models'` expiry on change/delete; e2e Despublicar |
| Slug path traversal / odd input | Tampering | `SLUG_RE` check before query; `notFound()` |
| Image rights dispute | Repudiation | `imageAuthorization` kept; versions; removal procedure in the staff guide |
